# 选题规划

先读取 `内容库/00-首页与维护规则/账号基本定位.md`，再遵循本 Skill 的 [历史库读取规则](references/history-vault-rules.md)。每次选题均由用户当次需求触发；不使用热点 API，也不按时段安排内容。

## 候选来源优先级

1. 用户本次指定的业务方向、客户类型或经营问题；
2. 历史库识别出的覆盖缺口与近期避重结果；
3. 对应业务选题池中状态为“可推荐”的候选；
4. 灵感库中状态为“可入池”的独立灵感；
5. 已发布内容的可延展选题；
6. 与账号定位一致的常青经营场景。

## 筛选与核验

依次检查定位匹配、场景完整、实质去重、事实边界和合规表达。重点比较近 7 天内容及同主题的全部历史内容；只换标题而客户场景、痛点或服务机会相同，仍视为重复。政策、税率、期限、处罚、平台规则和办理流程须核验当前官方来源；不能核验时改为不下确定性结论的场景题或标记待核验。

按客户与财税相关度 30、服务承接价值 25、场景紧迫性 15、内容缺口 15、近期差异度 10、事实可核验性 5 的权重排序。

## 输出与结束边界

输出 5 个彼此不复用客户场景、核心痛点或服务机会的方案。每项包含：自有化选题、目标客户与场景、服务关联、入选依据、核验状态、与近期历史内容的差异说明。

输出后等待用户选择、组合或调整；不得自动生成文案、写入历史内容库，或将候选视为已发布。
