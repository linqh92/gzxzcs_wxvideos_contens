# 视频号日更获客

将每次任务视为独立工作流。目标是通过合规、易懂的基础财税内容吸引广州有真实需求的创业者和中小微企业；以公司注册、代理记账获客为首要方向，不为播放量偏离业务承接。

## 必须遵守的顺序

1. **扫描知识库。** 先读取[知识库读取说明](references/obsidian-history-vault.md)，重新扫描当前 `内容库/01-历史内容`；历史笔记是去重和覆盖判断的唯一来源。无法读取或解析时，不输出正式选题。
2. **归纳覆盖与缺口。** 结合账号定位、近 7 天避重、长期缺口、客户问题和服务场景提出候选题；内容地图和复盘文档只作辅助。
3. **检索当天热点。** 完成历史扫描后，若 Token 可用，使用 `JustOneAPI-token.txt` 调用 Just One API，按 `DOUYIN`、`XIAOHONGSHU`、`WEIBO`、`WEIXIN` 检索 3—5 个公司注册、代理记账和基础财税关键词，默认最近 24 小时。只记录真实返回的数据，不虚构热度、时间、链接或跨平台验证结果；未配置 Token 时如实转入常规流程。
4. **核验与降级。** 政策、税率、优惠、期限、处罚、平台新规和办理流程必须补充当前官方来源。额度不足、接口失败、返回为空或结果无关时，记录状态并转入常规选题流程，不尝试其他 API。
5. **输出并确认选题。** 输出早、中、晚 3 条必发选题和 2 条备选，说明客户场景、服务关联、来源和核验状态；必发选题默认至少 2 条直接服务公司注册或代理记账，且不得复用同一客户场景、核心痛点或服务机会。等待用户确认，不替用户做最终选择。
6. **生成文案。** 只有用户确认具体时段选题后，才完整读取[原始文案生成指南](references/original-copywriting-guide.md)，并以其为唯一内容生成规范。未确认选题不生成定稿；只使用本次主题、资料和已核实公开信息。
7. **交付前检查。** 按原始文案指南和微信视频号规则完成真实性及合规检查，在文案底部附风险等级、风险原因、高风险要点和修改建议；高风险表达先改写再交付。
8. **等待发布反馈。** 用户确认文案后不写历史库，等待用户明确说明实际发布或更新了哪条内容。
9. **按唯一规范归档。** 发布信息无法唯一确认时先询问。归档前读取 `内容库/00-首页与维护规则/历史内容归档规范.md`；只有收到明确写入指令后，才新建笔记并按该规范更新索引与复盘。不得覆盖同名或疑似重复笔记；用户希望自行维护时只输出字段和路径。

## 垂直行业热点检索与筛选

### 检索顺序与来源边界

1. 完成本地历史库扫描和覆盖分析后，再进行垂直关键词检索；本地历史库仍是账号历史内容、去重和覆盖判断的唯一来源。
2. Just One API 的跨平台搜索接口为唯一外部 API 来源，按 `DOUYIN`、`XIAOHONGSHU`、`WEIBO`、`WEIXIN` 分别检索。接口地址使用 `https://api.justoneapi.com/api/search/v1`，中国大陆访问需要时可使用其文档提供的大陆节点。
3. 初始关键词池为：`广州注册公司`、`公司注册地址`、`经营范围`、`注册资本`、`股东`、`营业执照`、`银行开户`、`税务登记`、`代理记账`、`建账报税`、`零申报`、`小规模纳税人`、`发票`、`工商年报`、`个体户`、`社保个税`、`公司变更`、`公司注销`、`创业避坑`。每次任务根据历史缺口和有效政策选择 3—5 个主关键词。
4. Token 文件路径为 `JustOneAPI-token.txt`。执行检索时从该文件读取 Token，不在回答、日志、选题记录或其他项目文件中显示 Token 内容。

### Just One API 记录与边界

每次调用记录北京时间、HTTP 成功/失败状态、关键词、来源平台和原始链接。HTTP 错误、超时、Token 无效、返回为空、额度不足和权限错误都必须如实记录；不得虚构热度、排名、发布时间或跨平台验证结果。返回内容只用于发现行业讨论和判断时效，仍需结合官方来源核验。

### 初筛与淘汰

热点进入候选池前必须同时满足：

- 与创业、公司主体、注册、记账报税或老板经营决策直接相关；
- 能落到明确的客户场景和痛点，并自然承接注册、代理记账或基础财税咨询服务；
- 不依赖未经核验的税率、处罚金额、申报期限、办理流程或政策结论；
- 与近 7 天已发布内容不复用相同客户场景、核心痛点和服务机会。

下列内容直接淘汰，不参与评分：娱乐八卦、纯情绪或与目标客户无关的社会热搜；来源或原始链接无法追溯的信息；必须依靠夸大风险或绝对化措辞才能成立的话题；无法核验且需要作出确定性政策结论的话题。

### 候选题评分

对通过初筛的候选题按 100 分排序：

| 维度 | 分值 | 判断标准 |
| --- | ---: | --- |
| 注册及记账相关度 | 30 | 是否直接触及目标客户的创业或基础财税问题 |
| 服务承接价值 | 20 | 是否能对应明确的咨询或服务场景 |
| 时效与热度 | 15 | 是否当天发生、排名靠前或持续升温 |
| 客户紧迫性 | 10 | 是否需要立即准备资料、自查或处理 |
| 跨平台验证 | 10 | 是否在两个及以上来源出现，或被关键词搜索验证 |
| 历史内容缺口 | 10 | 是否补足长期未覆盖的场景 |
| 差异化表达空间 | 5 | 是否能避开近期标题和表达角度 |

高分不自动入选；仍须通过历史避重和事实核验。热度只能提高候选优先级，不能替代获客关联和合规判断。

### 事实核验与记录

1. 经营场景题可依据热点和通用合规建议创作，但避免输出未经确认的具体规则。
2. 政策、税率、申报期限、处罚、平台新规、工商税务办理流程等政策/规则题，必须补充当前官方来源；未核验前只可保留为候选，不得进入正式选题。
3. 每日热点记录建议保存至 `内容库/03-选题规划/垂直热点/YYYY/YYYY-MM/YYYY-MM-DD.md`。仅记录标题或关键词、来源平台、原始链接、搜索表现、采集时间、筛选结论、候选评分和核验状态。
4. 已核验且可长期复用的政策依据，可在用户确认后归档至 `内容库/05-内容素材库/政策资料.md`；未经核验的热点不得归档为政策资料。

### 失败降级

- Just One API 额度不足：停止 API 检索，转入常规选题流程。
- Just One API 其他接口失败：记录失败状态，转入常规选题流程。
- 垂直检索结果与账号业务无关：回到内容缺口、客户真实问题和待发布选题，生成常青选题。
- 政策无法核验：改为不含确定性政策结论的经营场景题，或作为备选保留。
- 同一接口连续 3 个选题日不可用：暂停将其作为正式来源，待人工复核后再恢复。

### 常规选题流程

1. 依据本地历史库的覆盖缺口、近 7 天避重结果、目标客户真实问题和服务承接场景提出候选题。
2. 通过公开网页和当前官方政策来源人工核验时效信息；不调用其他外部数据 API。
3. 无法获得可靠热点信息时，优先生成不依赖即时热点的公司注册或代理记账经营场景题，并在选题依据中标明未使用 API 热点数据。

## 历史库规则

- Obsidian 仓库是账号历史内容的唯一来源。
- 一条已发布视频只建立一篇笔记，按发布日期归档，分类使用 frontmatter 属性。
- `business_line` 表示业务板块，`theme` 表示具体内容主题，不得混用。
- 每日扫描必须覆盖用户可能手动新增、删除或修改的笔记；索引与历史笔记冲突时，以历史笔记为准并修复索引。
- 历史记录用于选题去重和覆盖分析，不作为当前政策有效性的证明。
- 历史笔记统一遵循 `内容库/00-首页与维护规则/历史内容归档规范.md`，固定字段值以 `固定选项库.md` 为准。

## 内容红线

- 不编造政策、案例、数据、金额、比例或处罚结果；不把个案或地方规定说成普遍规则。
- 不制造恐慌，不承诺包过、节税效果或零风险，不传播逃税、虚开或规避审核的方法。
- 不写内部渠道、特殊关系，不要求点赞、关注、转发、评论暗号或私信领取资料。
- 不输出镜头、画面、字体、动画或版式建议；正文必须可独立阅读。
