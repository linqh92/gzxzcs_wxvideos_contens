# 视频号日更获客

将每次任务视为独立工作流。目标是通过合规、易懂的基础财税内容吸引广州有真实需求的创业者和中小微企业；以公司注册、代理记账获客为首要方向，不为播放量偏离业务承接。

## 必须遵守的顺序

1. **重新扫描本地历史库。** 按[知识库读取说明](references/obsidian-history-vault.md)读取当前 Obsidian 仓库。每次重新列出 `内容库/01-历史内容` 下全部笔记，提取 `title`、`publish_date`、`business_line`、`theme`、`content_type`、`audience`、`pain_scene`、`content_goal`；阅读最近 30 条和拟议同主题笔记正文。仓库不可读取或结构无法可靠解析时，说明阻碍，在修复前不输出声称已避重的正式选题。
2. **归纳历史覆盖。** 识别已覆盖业务、客户场景、痛点、内容类型、标题角度、服务机会、近 7 天重复主题和长期缺口。`02-内容地图` 与 `04-内容复盘` 只作辅助；判断以当前历史笔记为准，以捕获手动修改。
3. **检索并筛选当天行业热点。** 按“垂直行业热点检索与筛选”执行 Just One API 检索；外部信息只用于发现创业、公司注册和基础财税的讨论与时效。涉及政策、税率、优惠、期限、处罚或办理流程时，必须核验当前官方来源。额度不足或接口失败时，转入常规选题流程。
4. **提出每日选题。** 输出早、中、晚各 1 条必发选题，另给 2 条备选。3 条必发默认至少 2 条直接服务公司注册或代理记账，第三条可为个体户、发票、年报、社保个税等能承接基础财税咨询的主题。三条不得复用同一客户场景、核心痛点或服务机会。
5. **等待选题确认。** 仅在用户明确确认对应时段选题后撰写该条文案；未确认时不生成定稿。
6. **生成文案。** 先完整读取[原始文案生成指南](references/original-copywriting-guide.md)，以其具体规则和最终格式为准；[文案指南摘要](references/copywriting-guide.md)只作快速索引。每条正式方案必须包含 3 个内容标题、1 个常规标题（搜索权重）、1 个 16 字内且无标点或特殊符号的短标题和正文；只使用该次确认主题、用户资料及已核实公开信息。
7. **方案风险评估。** 交付前按[微信常见违规内容概述](https://weixin.qq.com/cgi-bin/readtemplate?lang=zh_CN&t=weixin_agreement&s=video_guide&head=true)及原始指南检查。方案底部附风险等级、风险原因、高风险要点和修改建议；高风险表达必须先改写。重点检查无依据承诺、虚假或绝对化表述、暗示代办或保证结果、夸大风险、诱导交易和用户纠纷可能。
8. **等待实际发布反馈。** 用户确认文案后结束制作步骤，不预先写入历史库；等待用户明确说明实际发布了哪条内容。
9. **准备历史笔记。** 用户说明已更新或已发布时，唯一识别实际采用的时段、标题和正文，按仓库模板生成笔记预览；无法唯一识别时先询问。
10. **确认后写入本地库。** 只有收到明确“确认写入知识库”或等价指令后，才在 `内容库/01-历史内容/YYYY/YYYY-MM` 新建笔记，并同步更新内容地图、月度复盘、缺口统计和候选清单。不得覆盖同名笔记；冲突先报告。用户自行维护时，只输出字段与建议路径。

## 垂直行业热点检索与筛选

### 检索顺序与来源边界

1. 先完成历史扫描和覆盖分析，再检索；本地历史库是去重与覆盖判断的唯一来源。
2. Just One API 跨平台搜索接口是唯一外部 API 来源：`https://api.justoneapi.com/api/search/v1`；按 `DOUYIN`、`XIAOHONGSHU`、`WEIBO`、`WEIXIN` 分别检索。中国大陆访问需要时使用其文档提供的大陆节点。
3. 主关键词从历史缺口和有效政策中选择 3—5 个，初始池：`广州注册公司`、`公司注册地址`、`经营范围`、`注册资本`、`股东`、`营业执照`、`银行开户`、`税务登记`、`代理记账`、`建账报税`、`零申报`、`小规模纳税人`、`发票`、`工商年报`、`个体户`、`社保个税`、`公司变更`、`公司注销`、`创业避坑`。
4. Token 文件为项目根目录 `JustOneAPI-token.txt`。只在文件实际存在且可读时使用；不得在回答、日志、选题记录或其他项目文件显示 Token 内容。

### Just One API 垂直检索清单

每次“规划选题”任务完成历史扫描后、生成候选题前，若 Token 可用则调用 API，并记录北京时间、HTTP 成功/失败状态、关键词、平台和返回中的原始链接。Token 不存在时如实写“未配置，使用常规流程”，不得阻塞常青选题。

1. 对 3—5 个主关键词分别请求四个平台，默认最近 24 小时；读取标题、摘要、发布时间、来源平台和原始链接。
2. 只能依据本次实际返回填写摘要；HTTP 错误、超时、Token 无效、返回为空、额度不足和权限错误均如实记录，不得虚构热度、排名、链接或跨平台验证。
3. 返回 `code=303`、HTTP 429、`code=601` 或 `code=602` 时，停止本次调用，不尝试其他 API，进入常规选题流程。
4. API 结果只用于发现讨论与时效；政策、税率、处罚、申报期限和办理流程仍须以官方来源核验。

### 初筛、评分与归档

候选题必须同时满足：与创业、公司主体、注册、记账报税或老板经营决策直接相关；能落到明确场景并承接注册、代理记账或基础财税咨询；不依赖未核验的确定性规则；不复用近 7 天相同场景、痛点和服务机会。

直接淘汰娱乐八卦、纯情绪热搜、无法追溯来源、只能靠夸大风险成立、需要未核验政策结论的话题。

| 维度 | 分值 | 判断标准 |
| --- | ---: | --- |
| 注册及记账相关度 | 30 | 是否直接触及目标客户的创业或基础财税问题 |
| 服务承接价值 | 20 | 是否对应明确咨询或服务场景 |
| 时效与热度 | 15 | 是否当天发生、持续升温或有明显讨论 |
| 客户紧迫性 | 10 | 是否需要立即准备资料、自查或处理 |
| 跨平台验证 | 10 | 是否在两个及以上来源出现或被关键词验证 |
| 历史内容缺口 | 10 | 是否补足长期未覆盖场景 |
| 差异化表达空间 | 5 | 是否避开近期标题和表达角度 |

高分不自动入选，仍须历史避重与事实核验。每日热点记录建议保存为 `内容库/03-选题规划/垂直热点/YYYY/YYYY-MM/YYYY-MM-DD.md`，记录关键词、平台、链接、搜索表现、采集时间、筛选结论、评分和核验状态；仅在用户确认后，将可长期复用的官方政策依据归档到 `05-内容素材库/政策资料.md`。

### 失败降级与常规选题

- 额度不足或接口失败：记录状态，停止 API 调用，转入常规流程。
- 热点与目标客户无关：依据内容缺口、真实问题和待发布选题生成常青题。
- 政策无法核验：改为不含确定性结论的经营场景题，或保留为备选。
- 同一接口连续 3 个选题日不可用：暂停作为正式来源，待人工复核后恢复。

常规流程：依据本地历史缺口、近 7 天避重、客户真实问题与服务场景提出候选；只用公开网页和当前官方来源人工核验时效信息；无法得到可靠热点时，优先生成不依赖即时热点的注册或记账常青题，并标明未使用 API 热点数据。

## 历史库规则

- Obsidian 仓库是账号历史内容唯一来源；已发布视频一条一笔记，按发布日期归档，分类使用 frontmatter 属性。
- `business_line` 表示业务板块，`theme` 表示具体内容主题，不得混用。
- 每日扫描必须反映手动新增、删除和修改；索引与历史冲突时以历史笔记为准并修复索引。
- 历史记录用于去重和覆盖分析，不作为当前政策有效性的证明。
- 新笔记采用 `内容库/00-首页与维护规则/视频内容模板.md` 和 `固定选项库.md` 的统一口径。

## 内容红线与资源

- 不编造政策、案例、数据、金额、比例或处罚结果；不把个案或地方要求说成普遍规定。
- 不制造恐慌，不承诺包过、节税效果或零风险，不传播逃税、虚开或规避审核的方法。
- 不写内部渠道、特殊关系；不要求点赞、关注、转发、评论暗号或私信领取资料。
- 不输出镜头、画面、字体、动画或版式建议；正文可独立阅读。
- 每日选题前完整读取[知识库读取说明](references/obsidian-history-vault.md)；生成正式文案前完整读取[原始文案生成指南](references/original-copywriting-guide.md)。
